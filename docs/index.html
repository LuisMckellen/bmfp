Bucket Minister Fullerene Protocol

A soccer-ball network, designed at 2 AM. Now measured.

BMFP is a peer-to-peer overlay for edge and IoT clusters, shaped like a C60 molecule. It started as a design journal written by a first-year computer science student. The journal ended by asking for a program. This site replays that program's runs and shows what it found.

It was 2 AM. I had college the next day. I was answering a systems design quiz when I had a thought: “What if a network was shaped like a fullerene?”

Then I looked at the chemistry: “Why not use resonance to rotate active nodes?” I asked. “Why not use VSEPR to push load away from hot nodes?”

            MeshGuard

            BMFP assumes a node either works or is dead. Real sensors also drift, stick and go quiet while still answering. MeshGuard asks how you notice that without labelled data. Several hand-written rules vote on every reading. A Dawid–Skene label model learns how far to trust each rule. Rules that go bad in one zone are quarantined, the scores are calibrated, and the model may abstain when unsure. It runs on a simulated ring of sensors; nothing here has met real hardware.

                Learning log

                Most of the protocol turned out to be re-inventions. That is the useful part: each invented word maps onto a real one with decades of work behind it, and the mapping is the fastest route into that work.

                Journal Part VIII, “What I Learned”, written by Claude (Anthropic) per the README
                My wordThe real nameWhat I now know
                The networking half · from the journal
                BiscuitPacketThe unit that gets routed, dropped, retried and reordered independently of the message.
                CheckpointRouter, or hopEvery hop is a place where a packet can be delayed, dropped or observed.
                Locked boxEnd-to-end encryptionOnly endpoints hold keys. Intermediate nodes route without reading.
                Got itAcknowledgementThe basis of reliable delivery. No ack means resend, which means duplicates, which means the receiver must dedupe.
                Numbering biscuitsSequence numbersOrdering and reassembly. TCP does this, and it is why multipath is harder than it looks.
                Chill and hell modeAdaptive and multipath routingSwitching routing strategy on load is real. Multipath costs either bandwidth or head-of-line blocking.
                Resend if lostARQ, automatic repeat requestStop-and-wait, go-back-N and selective repeat are the standard families.
                Anti-spam limitRate limiting, token bucketA well-defined algorithm with a burst size and a refill rate, not just a cap.
                Path rotationTraffic analysis resistanceChanging paths hides patterns from an observer watching one link. Tor exists for this.
                One send, fifty deliveriesApplication-layer multicastThe tree is built in the overlay because IP multicast is not deployed on the open internet.
                Splitting a big groupSharding, or partitioningThe hard part is not splitting. It is routing between the parts and keeping labels straight.
                Gate passGroup key, or access tokenShared-secret schemes have a removal problem. MLS solves it with a key tree.
                The systems half · from the journal
                Ghost, active, standbyMembership statesKeeping every node agreeing on who is in which state is the actual problem, and it is called membership.
                CaptainLeader, or coordinatorElecting one is a solved but expensive problem. Raft is the standard answer, and it assumes stable membership.
                Cell hibernateScale to zeroServerless platforms do exactly this. The interesting number is the cold start, not the saving.
                ResonanceRole rotationRotating a role for fairness and unpredictability is real. Delocalisation is a good picture, not a mechanism.
                VSEPR repulsionFeedback control, load balancingAny threshold-driven loop needs hysteresis and damping, or it oscillates. Control theory has the vocabulary.
                Stem nodes and DNAReplicas and snapshotsA checkpoint written to several places is a snapshot with a replication factor.
                Death detectionFailure detectionSWIM is the readable one: gossip plus indirect probes. Detection time trades against false positives.
                Mitosis and meiosisPartial and total failure recoveryDifferent failure modes get different recovery paths. Naming them separately was the right instinct.
                Regeneration under 500 msRTO and RPORTO runs from the failure instant, not from when recovery starts. RPO is how much data the last checkpoint can lose.
                Atomic state mapThe CAP tradeoffUnder a partition you get consistency or availability. Gossip chose availability, and that choice has to be stated.
                Graphite modeHierarchical overlay, DHTRouting between cells needs a lookup scheme. Kademlia is the one to read.
                The whole thingAn overlay networkRunning on top of IP rather than replacing it is what makes any of this testable on a laptop.
                Added by this build · from writing the simulator
                Valid ACTIVE set addedConnected dominating setEvery node is ACTIVE or next to an ACTIVE node, and the ACTIVE nodes stay connected to each other. Ad-hoc networking calls this a virtual backbone. The simulator checks it after every state change.
                The simulator loop addedDiscrete-event simulationTime jumps from one scheduled event to the next in a priority queue. Ties break by insertion order, so the same seed always replays the same run.
                Damping VSEPR addedHysteresis and a cooldownA node that just changed state may not change back for a few cycles, and only a few nodes may change per cycle. This is the fix the review asked for.
                A relay's capacity addedToken bucketEach relay refills tokens at a fixed rate up to a burst size. A hop that finds no token is a congestion drop.
                Hell mode, two readings addedDuplication versus stripingDuplication sends a full copy down each disjoint path and needs one to arrive. Striping splits the message across paths and needs every piece.
                No single failure cuts the ball addedVertex connectivityThe fewest nodes whose loss disconnects the graph. Disjoint paths and minimum cuts are two views of the same number.
                Captain election addedDeterministic rotation over a membership viewEvery node that sees the same view computes the same captains. A split view would elect two sets, which the simulator does not model.
                The moment before detection addedStale viewBetween a failure and its detection, senders route on a membership view that is out of date. Those drops have their own name in the data: stale_view.
                “More than half” addedA strict thresholdLosing exactly half does not raise the death event. A boundary written in words needs a test at the boundary.

                Reproduce every number

                Every measured number on this page is read from two data files, and both files are written by commands in this repository. The page's own text quotes only the journal's design targets (on the ladder) and the definitions of the measures. Run the commands yourself, from the repository root.

                1. Install both packages.
                  pip install -e bmfp -e meshguard
                2. Run the simulator's experiments. They write tables, plots and findings to reports/.
                  bmfp experiments --out reports/
                3. Export the simulator data this site reads.
                  bmfp export-web --out docs/data
                4. Export the MeshGuard results.
                  meshguard export-web --out docs/data
                5. Serve the site, then open http://localhost:8000.
                  python -m http.server -d docs 8000
